01 · Princípios

Constitution

O que é importante mesmo quando a tarefa muda.

Princípios→Valores→Trade-offs→Limites
02 · Como trabalhamos

Instructions

Padrões, convenções, regras e restrições que reduzem decisões repetitivas.

Não confundir

Instruction não é objetivo, conhecimento genérico ou missão.

03 · Execução recorrente

Skills

Conhecimento → procedimento reutilizável → execução.

Uma skill evita que cada agente invente novamente o caminho para uma atividade recorrente.

04 · O mundo real

Context

Produto→Sistema→Arquitetura→Cadastro→Usuário

O que existe? Por que fazer? Quem é afetado? Quais restrições?

05 · Contrato de execução

Mission

Contexto + Objetivo + Restrições + Critérios de aceite.

Uma missão define o resultado esperado sem precisar ditar cada tecla.

Decomposição

Responsabilidade antes de personalidade.

Objetivo → Resultados → Responsabilidades → Dependências → Missões → Evidências

Delegar é distribuir contexto, responsabilidade e critérios de sucesso.

Principal Engineer → Orquestrador

Seu trabalho não desaparece. Ele sobe de nível.

Definir

Objetivos, fronteiras e critérios de sucesso.

Arquitetar

Dependências, decisões e decomposição.

Revisar

Qualidade, riscos, trade-offs e evidências.

Integrar

Transformar trabalhos independentes em um sistema coerente.

Fechamento

Não é uma fábrica de prompts.

É uma fábrica de trabalho bem organizado.

Bons objetivos → bons contextos → boas missões → bons agentes → boas evidências.
