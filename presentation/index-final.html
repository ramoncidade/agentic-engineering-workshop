01 · Princípios

Constitution

O que é importante mesmo quando a tarefa muda.

Princípios→Valores→Trade-offs→Limites
Pietro · exemplo

Constitution: uma bússola, não um manual.

Bom

Princípio

“Preferimos soluções simples e observáveis. Complexidade precisa comprar uma capacidade clara.”

Ruim

Lista de tarefas

“Use Spring Boot. Crie controller. Crie service. Rode o build.” Isso ensina como, não o que valorizar.

02 · Como trabalhamos

Instructions

Padrões, convenções, regras e restrições que reduzem decisões repetitivas.

Não confundir

Instruction não é objetivo, conhecimento genérico ou missão.

Pietro · exemplo

Instructions: guardrails para trabalhar.

Bom

Regra reutilizável

“Toda API externa deve ter timeout explícito, tratamento de erro e métricas de latência.”

Ruim

Conhecimento solto

“Timeouts são importantes.” Verdadeiro, mas não orienta o trabalho neste sistema.

03 · Execução recorrente

Skills

Conhecimento → procedimento reutilizável → execução.

Uma skill evita que cada agente invente novamente o caminho para uma atividade recorrente.

Pietro · exemplo

Skills: ensinar um caminho que pode ser repetido.

Bom

Skill de integração

Entrada: endpoint + contrato. Processo: cliente, timeout, retry, rate limit e testes. Saída: integração validada.

Ruim

“Faça uma integração”

O agente reinventa o processo em cada projeto. Resultado: variação e inconsistência.

04 · O mundo real

Context

Produto→Sistema→Arquitetura→Cadastro→Usuário

O que existe? Por que fazer? Quem é afetado? Quais restrições?

Pietro · exemplo

Context: o mapa antes da rota.

Bom

Contexto suficiente

“O cadastro entra no app bancário, exige CPF único, integra identidade existente e precisa manter compatibilidade com clientes atuais.”

Ruim

Contexto zero

“Crie um CRUD de usuário.” Tecnicamente claro. Arquiteturalmente, quase inútil.

05 · Contrato de execução

Mission

Contexto + Objetivo + Restrições + Critérios de aceite.

Uma missão define o resultado esperado sem precisar ditar cada tecla.
Pietro · exemplo

Mission: pedir resultado, não coreografia.

Bom

Missão verificável

“Implemente o cadastro preservando compatibilidade. Critério: CPF único, testes de integração e pipeline verde.”

Ruim

Prompt coreografado

“Abra o arquivo X, escreva Y, depois rode Z...” O humano dirige cada tecla.

A pergunta inevitável

“Preciso lembrar tudo isso sozinho?”

Não. O sistema precisa lembrar por nós.

Decomposição

Responsabilidade antes de personalidade.

Objetivo → Resultados → Responsabilidades → Dependências → Missões → Evidências

Delegar é distribuir contexto, responsabilidade e critérios de sucesso.

Paralelismo

Nem tudo precisa ser paralelo.

descoberta

Como eu sei que posso confiar?
