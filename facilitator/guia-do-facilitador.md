# Guia do facilitador

## Objetivo do workshop

Levar participantes a perceber que trabalhar com IA de forma agentic não é principalmente uma questão de escrever prompts melhores. É uma questão de projetar um sistema de trabalho.

Ao final, o participante deve conseguir:

- definir um objetivo observável;
- separar princípios, regras, capacidades, responsabilidades e contexto;
- transformar uma demanda em missões executáveis;
- identificar trabalho paralelizável;
- definir fronteiras entre agentes;
- exigir evidências de execução;
- reconhecer o que continua sendo responsabilidade humana.

## Duração sugerida

**2h30**.

A duração pode ser reduzida, mas o exercício de decomposição não deve ser eliminado. Ele é o ponto em que a ideia deixa de ser conceitual.

## Como conduzir

### Não entregue a taxonomia cedo demais

No começo, faça perguntas.

Se o grupo receber imediatamente os nomes Constituição, Instruções, Skills e Contexto, existe o risco de decorar categorias sem entender o problema que elas resolvem.

O ideal é fazer a turma sentir a falta de informação antes de apresentar o nome daquilo que está faltando.

### Use o engenheiro como personagem

A abertura funciona melhor como uma situação real:

> “Contratamos o melhor engenheiro de software que existe. Agora entreguem uma demanda para ele.”

Quando surgir uma resposta vaga, pergunte:

> “O que ele ainda não sabe?”

Quando surgir uma regra, pergunte:

> “Isso é uma regra de decisão ou uma regra de trabalho?”

Quando surgir um agente, pergunte:

> “Qual responsabilidade desapareceria se esse agente não existisse?”

### Evite transformar o workshop em demonstração de ferramenta

Ferramentas são importantes, mas são consequência da arquitetura do trabalho.

O objetivo é que o participante consiga aplicar os conceitos mesmo usando outro modelo, outro editor ou outra plataforma amanhã.

## Perguntas de provocação

Use algumas destas perguntas quando a discussão esfriar:

- O que acontece se o agente não conhecer a arquitetura atual?
- O que acontece se dois agentes tomarem decisões incompatíveis?
- Quem decide quando duas soluções tecnicamente corretas entram em conflito?
- Como sabemos que um agente realmente terminou?
- Quando dois agentes são paralelismo e quando são apenas duas pessoas editando a mesma coisa?
- O que você não delegaria mesmo tendo um agente excelente?
- Se trocar o modelo de linguagem amanhã, qual parte do seu sistema continua válida?

## Critério de sucesso

O workshop funcionou se o participante terminar pensando menos em prompts e mais em:

> **objetivo → contexto → responsabilidade → execução → evidência → decisão**

Não é necessário que todos saibam configurar um framework de agentes ao final. É mais importante que saibam desenhar o trabalho que um framework deverá executar.
